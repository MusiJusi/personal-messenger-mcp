# Personal Messenger MCP

Локальный помощник для личного Telegram-аккаунта. Читает переписки и каналы,
ищет сообщения и отправляет текст от вашего имени по запросу.

Модель работает в LM Studio, а MCP-сервер предоставляет ей доступ к Telegram
через Telethon. Сводки и ответы составляет сама модель.

```text
Запрос → LM Studio + модель → MCP-сервер → Telegram
```

## Установка на Windows

Понадобятся Git, Python 3.11+ и LM Studio с моделью, поддерживающей вызов инструментов.
Проект проверен с Qwen3.5-9B в формате GGUF, квантизация Q4_K_M.
Требования к памяти зависят от выбранной модели и размера контекста.

Выполните в PowerShell:

```powershell
git clone https://github.com/MusiJusi/personal-messenger-mcp.git
cd personal-messenger-mcp
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

Подключите сервер к LM Studio:

```powershell
.\.venv\Scripts\python.exe -m personal_mcp install-lmstudio
```

Команда обновляет `%USERPROFILE%\.lmstudio\mcp.json`, сохраняя другие подключения
и резервную копию настроек. Откройте чат в LM Studio, загрузите модель и включите
`personal-messenger` в меню инструментов. MCP-сервер запускается самим приложением.

## Проверка без Telegram

По умолчанию включён режим `demo`: вымышленные переписки и имитация отправки.
Попросите модель:

> Вызови server_status и скажи, в каком режиме работаешь.

> Найди адрес встречи в переписке с Игорем. Укажи ID сообщения.

Ожидаемый результат: Москва, Лесная улица, 7, кафе «Пример»; сообщение `2`.

## Подключение Telegram

1. Получите собственные **API ID** и **API hash** на [my.telegram.org/apps](https://my.telegram.org/apps).
   Нужны реквизиты клиентского приложения, а не токен бота.
2. Выполните команду и введите реквизиты, телефон, код входа и пароль 2FA, если он включён:

   ```powershell
   .\.venv\Scripts\python.exe -m personal_mcp login
   ```

3. После успешного входа режим `telegram` сохранится в `.env`.
   Перезапустите `personal-messenger` в LM Studio и снова вызовите `server_status`.

Реквизиты и коды вводятся только в локальном терминале. `.env` и `.state/` исключены
из Git. Файл `.state/account.session` хранит авторизацию Telegram; архив переписок
сервер не создаёт. Не передавайте эти файлы другим людям.

## Примеры запросов

> Найди канал «название» и сделай сводку последних пяти публикаций со ссылками.

> Найди в переписке с «имя» сообщения об адресе встречи за последнюю неделю.

> Отправь в моё Избранное сообщение «Проверка локального помощника».

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `server_status` | Проверка подключения, режима и часового пояса |
| `list_chats` | Список чатов, групп и каналов, поиск по названию или username |
| `get_messages` | Чтение сообщений с фильтром по датам и постраничной загрузкой |
| `get_message` | Чтение конкретного сообщения, включая полный текст |
| `search_messages` | Текстовый поиск внутри выбранного чата или канала |
| `send_message` | Отправка текста или ответа на сообщение |

## Настройки

Редактируются в `.env`; образец — [.env.example](.env.example).
Переменные окружения имеют приоритет, относительные пути считаются от папки проекта.

| Переменная | Назначение |
| --- | --- |
| `MESSENGER_MODE` | `demo` или `telegram` |
| `TELEGRAM_SESSION` | Путь к сессии; по умолчанию `.state/account` |
| `MESSENGER_TIMEZONE` | Часовой пояс; по умолчанию `Europe/Moscow` |
| `TELEGRAM_ALLOWED_CHAT_IDS` | Разрешённые ID через запятую; пустое значение разрешает все доступные диалоги |
| `TELEGRAM_READ_ONLY` | При `true` инструмент отправки отключён |

## Ограничения

- Обрабатывается текст и подписи к вложениям. Скачивания файлов, анализа изображений
  и распознавания голосовых пока нет; секретные чаты не поддерживаются.
- Поиск выполняется внутри одного чата. Для нескольких источников модель вызывает
  инструменты последовательно; списки сообщений выдаются страницами до 30 записей.
- Длинный текст в списке сокращается; полный текст доступен через `get_message`.
- Работа выполняется по запросу из LM Studio. Фонового мониторинга и расписания пока нет.
- Отправляется обычный текст. При повторе одного поручения используется прежний
  `request_id`; при неизвестном результате отправки сначала проверьте чат.

При работе с содержимым Telegram учитывайте его [условия использования](https://telegram.org/tos/content-licensing).

## Проверки и устройство проекта

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe scripts\smoke_mcp.py
```

Проверки используют демоданные и не отправляют реальные сообщения.
Для проверки модели включите локальный API-сервер в LM Studio и запустите
`scripts/check_lmstudio.py` через Python из `.venv`; он также использует только `demo`.

- `src/personal_mcp/server.py` — MCP-инструменты.
- `src/personal_mcp/service.py` — проверки, даты, пагинация и повтор отправки.
- `src/personal_mcp/backends.py` — подключение Telegram и демоданные.
- `src/personal_mcp/cli.py` — запуск, вход, диагностика и настройка LM Studio.
- `tests/` — автоматические проверки.
